# Cycle 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reshape Flat Attack scaling into a capped log curve, split the boss into three 2,000-HP stages, reward playing close to the boss, add a flashing E and a killing-shot impact frame, and keep win-rate data separated by balance version.

**Architecture:**
- **Damage:** one `logCurve` helper in `src/stats.ts` drives both ATK and AMP. A `closeBonus(w)` multiplier is applied when a shot or the beam fires.
- **Boss stages:** live in `enemies.ts`, through `damageBoss`, `bossDefeated`, and a refill countdown on the boss. `combat.ts` and `round.ts` call those instead of touching `boss.hp` directly.
- **New visuals:** the flashing E and the impact frame are rectangles in `draw.ts`.

**Tech Stack:** TypeScript (strict), Vite, Vitest (+ happy-dom), raw WebGL2. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-cycle-2-design.md`

## Global Constraints

- Branch `feat/cycle-2`. **No commits unless the owner says so.** Each task ends with a green `npm test`.
- All tunables live in `src/config.ts`. No allocation inside `stepWorld`. Boxes are centre-based.
- Baseline: 28 files, 218 tests passing.

## Review Focus

1. **Stage boundary on the same step as other damage** (a beam and bullets in one step, or overkill). Exactly one stage advance, the leftover damage is lost, and the round is not won early. Test in Task 3.
2. **Damage while the bar refills.** Bullets are used up and the beam deals nothing. No killing shot happens during the refill. Tests in Tasks 3 and 4.
3. **Zero-width movement area** (`area.w = 0`, up/down-only mode). The close bonus is ×1.0 and never NaN. Test in Task 2.
4. **Win-rate log records from before this change** (no `balanceVersion`). They load as version 1, are not counted under version 2, and survive F4. Test in Task 7.
5. **Stress mode** (`?stress`, stage 3, 0 damage). It never advances a stage or wins. Checked in Task 8, in the browser.

**Interfaces:**
- Produces, in `enemies.ts`:
  - `damageBoss(w: World, amount: number): boolean`. It returns false (no change) while `charge > 0` or once the boss is defeated. Otherwise it lowers `hp` (floor 0) and pushes `bossHit`. If `hp` hits 0 and `phase < phases.length`, then `phase++`, `charge = chargeTime`, and it pushes `phaseChanged`.
  - `bossDefeated(b: Boss, stages: number): boolean`, true when `b.phase === stages && b.hp <= 0 && b.charge <= 0`.
  - `updateBoss` does the refill: while `charge > 0` it counts `charge` down and sets `hp = maxHp × (1 − charge / chargeTime)`. It still moves, but launches no drones and fires no patterns. `phaseFor` is deleted.
- Produces, in `testUtils.ts`: `defeatBoss(w: World): void`, which sets `phase` to the last stage, `hp = 0`, `charge = 0`.
- Uses:
  - `combat.ts` calls `damageBoss` for bullets and the beam. A bullet that overlaps the boss is always used up.
  - `round.ts` wins on `bossDefeated`.
  - `draw.ts` draws the boss unless it's defeated.
  - Stress mode sets `phase = 3` and `hp = maxHp`.
- Dev console BOSS line: `BOSS stage n/3 · HP h/2000 (p%) · charge c s · pos x,y`.
